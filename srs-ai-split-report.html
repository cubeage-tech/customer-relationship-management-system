    Limitations and assumptions

    • Statuses, evidence, gaps and remaining work come unchanged from srs-compliance-report.html (same IDs). Three new audit findings were added as NEW-AI-01…03; nothing was dropped or merged.
    • The AI inventory comes from a full-text search of backend and frontend source, pom.xml, package.json, migrations and env examples for provider SDKs, model names, keys, prompts, embeddings and vector stores. Nothing in the code calls an AI service, so every AI-Core item is Not Started.
    • Because no AI exists, providers, files, prompts and contracts on AI-Core cards are proposed designs (marked "to create"), not descriptions of existing code. The JSON shapes are suggested contracts for developers to agree on.
    • Track rule: AI-Core = the feature is the model/LLM; AI-Dependent = a normal feature that needs AI output; everything else is AI-Independent. FR-4.8, FR-AI-7.1 and FR-AI-8.1 sit in the SRS's AI sections but were classed AI-Independent with a "Needs Decision" note explaining why.
    • Owner skills (Frontend / Backend / DB / DevOps / AI-Prompt-Engineer) are a suggestion for the lead. Mobile (Flutter) work is listed under Frontend because no mobile skill was specified.
    • Priorities are the estimates from the first report; the SRS states none. Effort is the largest effort among an item's tasks.
    • No code was run for this report. The audited code includes uncommitted changes on dev_ajinkya.
    • Checkbox progress is saved in this browser's localStorage only.
