Every open P0 and P1 item, ordered so dependencies come first (e.g. Docker → CI/CD → health checks → monitoring → rollbacks).

    Roadmap

    Phase 1 before go-live (P0/P1), Phase 2 first month (P2), Phase 3 at scale (P3 and Not-Applicable-Now triggers). A dependency is pulled into the earlier phase when needed.

    Developer task board

    Open items with a plan, grouped by owner skill. "Copy task" copies the full task with steps, files and acceptance criteria as Markdown.

    Limitations and assumptions

    • Static audit of the repository only. Nothing was deployed, load-tested or probed at runtime; items that depend on the live environment are marked Cannot Verify.
    • Infrastructure outside the repo (hosting accounts, DNS, CDN settings, managed-database backups/HA, secret stores) was not visible. The backend's production host is not defined anywhere in the repo.
    • "Implemented" means the configuration or code was opened and confirmed in use, not just that a package or file exists.
    • Secrets found in the repository are referenced by file and line only; values are not reproduced in this report or in readiness-tasks.json.
    • Not Applicable Now items are judged against this project's current size (one Spring Boot service, one PostgreSQL database, an India-first SaaS with the SRS 99.5 % uptime target); each lists the trigger that would make it necessary.
    • Score: Implemented = 1, Partial = 0.5, everything else = 0, over applicable topics. Ticking Done counts an item as Implemented; a status changed from the dropdown is used in the score. Both are saved in this browser only.
    • Re-run: ticks are stamped with the audit date. When a newer audit is opened, ticks on items the code still doesn't show as Implemented are dropped and listed under "Changes since last audit".
